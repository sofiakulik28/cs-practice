## Разбор команд: git diff и git log

**git diff** — показывает разницу между рабочей директорией и индексом (staging area), либо между двумя коммитами. Эта команда показывает только сами изменения (какие строки добавлены, а какие удалены), без информации об авторе и дате коммита. Она используется для просмотра незакоммиченных изменений или сравнения версий файлов.

**git log** — показывает историю коммитов репозитория. По умолчанию выводит список всех коммитов с их хэшами, авторами, датами и сообщениями. Эта команда не показывает сами изменения в файлах, а служит для навигации по истории и понимания того, какие коммиты были сделаны. С флагом `-S"текст"` команда `git log` ищет коммиты, в которых изменялось количество вхождений указанной строки.

**git show** — показывает полную информацию о конкретном коммите: автора, дату, хэш, сообщение и все внесенные в этом коммите изменения (аналог `git diff` для одного коммита).

**git restore** — восстанавливает файл из индекса или последнего коммита (HEAD).
**git restore --source=...** — восстанавливает файл из конкретного указанного коммита.
**git revert** — создает новый коммит, который отменяет изменения указанного коммита (безопасно для публичной истории).
**Тег** — постоянная метка на коммите, не двигается при новых коммитах.
**Ветка** — подвижный указатель на последний коммит в цепочке.## 3. Восстановление файла

**Чем `git restore` отличается от `git restore --source=...`:**
* `git restore` восстанавливает файл из индекса (staging area) или последнего коммита (HEAD).
* `git restore --source=...` позволяет взять версию файла из конкретного коммита (например, HEAD~2) и поместить её в рабочую директорию.

**Что произошло бы с правами:**
Если бы у файла были особые права доступа (например, исполняемый файл), команда `git restore --source=...` могла бы их сбросить, так как Git восстанавливает состояние файла из коммита, включая права доступа.
## 4. Отмена ошибочного коммита

**Чем `git revert` отличается от `git reset --hard`:**
* `git revert` создает **новый** коммит, который отменяет изменения, внесенные указанным коммитом. История не переписывается.
* `git reset --hard` перемещает указатель ветки на другой коммит, **удаляя** все коммиты после него из истории.

**Почему в опубликованной истории безопаснее `git revert`:**
В опубликованной истории безопаснее использовать `git revert`, так как `reset` ломает историю для других разработчиков, которые уже могли скачать старую версию.
## 5. Тег рабочей версии

**Чем тег отличается от ветки:**
* Тег — это постоянная метка на конкретном коммите, которая не двигается при новых коммитах.
* Ветка — это подвижный указатель, который всегда указывает на последний коммит в цепочке. Тег нужен для фиксации релизов, а ветка — для разработки.
